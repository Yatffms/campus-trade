# campus-trade 部署方案（原理 + 手动步骤 + 踩坑实录）

> 这篇文档写给"想弄明白为什么"的人，不是一份抄完就能跑的脚本。
> 阅读顺序建议：第一、二章先建立模型 → 第三章看你的机器长什么样 → 第四章照着手动做一遍 →
> 第五章对照我们真实踩过的坑 → 第七章拿去准备面试。

## 第一章 部署到底在解决什么问题

一句话：**把你电脑上"能跑"的东西，原样搬到一台 24 小时不关机的 Linux 上，并且让它在你不看着的时候也不挂。**

难的不是"传文件"，而是下面四样东西必须同时到位：

| 要素 | 在 campus-trade 里对应什么 | 缺了会怎样 |
|---|---|---|
| 运行时 | JRE 17 | `java: command not found`；或版本不对，class 文件版本报错 |
| 依赖服务 | MySQL 8、Redis、RabbitMQ | 应用启动即 `Connection refused`，或启动成功但一用就 500 |
| 配置 | 数据库地址、Redis 地址、密钥路径、`return_url` | 连的还是 `localhost`，容器里压根没有服务；支付宝回跳 404 |
| 数据 | 建表脚本、支付宝密钥、用户上传的图片 | 表不存在、签名失败、图片 404 |

所以部署工作的本质是：**把这四样分别放到服务器上，再用一份配置把它们串起来。**

> 记住一个判断法则：**任何"线上不对"的问题，先归类到这张表的某一行**，再去查那一行的细节，比乱翻日志快得多。

## 第二章 原理篇

### 2.1 从"进程"到"公网能访问"，中间有四道门

一个 Spring Boot 应用本质是一个 Java 进程，它做了一件事：**监听某个端口**（你的项目是 8080）。
但"进程在跑"和"别人能用浏览器打开"之间，隔着四道门，任何一道没开都表现为"打不开"：

```
第 1 道：进程真的在监听吗？        ss -lntp | grep 8080
第 2 道：容器端口映射到宿主机了吗？ docker ps 看 PORTS 列有没有 0.0.0.0:8080->8080/tcp
第 3 道：云厂商防火墙放行了吗？     控制台「防火墙/安全组」里有没有 8080
第 4 道：应用自己 bind 到 0.0.0.0 了吗？（Spring Boot 默认就是，不用管）
```

**排查顺序永远是从下往上**（进程 → 映射 → 防火墙 → 浏览器），因为越底层越容易出错，也越容易被忽略。

### 2.2 SSH：为什么用密钥而不是密码

SSH 是"远程登录一台 Linux"的协议，默认 22 端口。登录有两种凭证：

- **密码**：人要记、要输、能被爆破、脚本里不好用；
- **密钥对**：本地生成一对（私钥 + 公钥），公钥贴到服务器 `~/.ssh/authorized_keys`。登录时服务器发随机数，客户端用私钥签名，服务器用公钥验证。**私钥永远不离开你的机器**，所以不怕被中途截获。

两个必须知道的规则（我真实踩过）：

1. **权限必须严格**：`~/.ssh` 要 `700`、`authorized_keys` 要 `600`、属主必须是登录用户。权限一旦对组/其他人可读，sshd 会**静默忽略**这个文件，你看到的现象是"密钥明明传了，还是 Permission denied"。
2. **贴对用户的家目录**：云控制台的"网页终端"默认给你 **root** shell。你以 root 身份执行 `echo ... >> ~/.ssh/authorized_keys`，写进去的是 `/root/.ssh/`；而你要登录的是 `ubuntu` 用户，必须写到 `/home/ubuntu/.ssh/`。

生成密钥（本地执行一次就够）：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -C "deploy"
# 私钥 deploy_key（宝，别外传）  公钥 deploy_key.pub（贴到服务器）
```

### 2.3 Docker：三个词 + 三个机制

**三个词（务必用"光盘/开机/菜谱"这套类比记住）**

| 词 | 类比 | 你项目里 |
|---|---|---|
| 镜像 image | 一张装好系统的光盘，只读 | `mysql:8.0`、`eclipse-temurin:17-jre` |
| 容器 container | 用光盘开机跑起来的一个进程 | `campus-mysql`、`campus-app` |
| Dockerfile | 做这张光盘的菜谱 | 你项目没写，用的官方镜像 |

**三个机制（面试常问"它凭什么这么轻"）**

1. **namespace（命名空间）**——决定"进程能看见什么"。每个容器有自己的一套进程号、网络、主机名、挂载点，所以容器里的 `localhost` 是它自己，不是宿主机。
2. **cgroups（控制组）**——决定"进程能用多少资源"。这就是 `--memory 512m`、`-Xmx512m` 这类限制的底层。
3. **镜像分层**——镜像由多层只读文件系统叠加而成，多个镜像共享基础层。所以再拉一个基于 `alpine` 的镜像，往往只要几十 MB。

**和虚拟机的区别**：虚拟机里要再跑一个完整操作系统（几个 G、启动一分钟）；容器**共享宿主机的 Linux 内核**，只隔离进程的视野，所以秒起、几十 MB。

### 2.4 容器网络：为什么配置里写的是 `campus-mysql` 而不是 IP

Docker 可以建一个"虚拟局域网"（bridge 网络），加入它的容器之间可以**用容器名互相访问**——Docker 内置了 DNS。

```
docker network create campus
docker run -d --name campus-mysql --network campus ...
docker run -d --name campus-app   --network campus ...
```

于是应用的 JDBC 写成 `jdbc:mysql://campus-mysql:3306/...` 就能连上。

**为什么不能写 `localhost`？** 因为容器里的 `localhost` 指它自己。这是初学者第一大坑，报错是 `Connection refused`。

**为什么数据库不映射到公网？** 因为 3306 一旦暴露，几小时内就会被扫描器爆破。正确做法：容器之间用内网名互通，只有应用（8080）映射出去。

### 2.5 端口映射 ≠ 防火墙放行

这两件事经常被混为一谈，但它们解决的是不同的问题：

| | 端口映射 `-p 8080:8080` | 防火墙放行 |
|---|---|---|
| 在哪一层 | Docker（宿主机 iptables 转发） | 云厂商网络层 |
| 作用 | 把宿主机 8080 的流量转进容器 8080 | 允许公网流量到达这台机器的 8080 |
| 漏了会怎样 | 宿主机上 `curl localhost:8080` 通，公网不通 | 宿主机上通、映射也对，公网照样不通 |

**两个都要有**，而且排查时要分别确认。

### 2.6 配置外置：为什么 jar 里不能写死线上地址

jar 里内置的 `application.yml` 是**本地开发配置**：`localhost:3306`、`D:\alipay\...` 这种路径。

线上要换一套。做法不是改代码重新打包，而是**启动时告诉 Spring 去哪读配置**：

```bash
java -jar /app/app.jar \
  --spring.config.location=file:/app/ \
  --spring.config.name=application-prod
```

这条命令的意思是：配置文件从 `/app/` 目录找，文件名是 `application-prod.yml`。于是同一份 jar，本地跑本地配置、线上跑线上配置。

> 这就是"12-Factor App"里的"配置与代码分离"，也是面试爱问的点：**为什么不用 `-Dspring.datasource.url=...` 一个个传？** 因为项目一多、参数一长，命令行会失控；用配置文件可读、可版本化、可回滚。

### 2.7 数据持久化与初始化

**持久化**：容器是"一次性"的，删了就没了。所以三个中间件的数据目录必须挂到宿主机：

```bash
-v /opt/campus/data/mysql:/var/lib/mysql
-v /opt/campus/data/redis:/data
-v /opt/campus/data/rabbitmq:/var/lib/rabbitmq
```

容器重建、镜像升级，数据都还在。**判断标准**：`docker rm -f` 之后重建，数据还在，说明挂对了。

**初始化**：MySQL 官方镜像有个约定——首次启动（数据目录为空）时，会**自动执行**映射到 `/docker-entrypoint-initdb.d/` 下的 `.sql` 文件。这就是为什么你本地那 35 件商品、6 个用户会"凭空"出现在服务器上：

```bash
-v /opt/campus/sql:/docker-entrypoint-initdb.d:ro
```

注意 **只执行一次**：数据目录一旦有数据，它就不再跑了。想重新初始化，必须删掉数据目录（危险操作）。

### 2.8 启动顺序与"就绪"不是一回事

MySQL 容器 "Up" 了，不代表它能接受连接——它还要初始化数据目录、建库、建表，这个过程可能 10~30 秒。如果应用插队启动，就会 `Connection refused` 然后退出。

两种解法：

- **脚本轮询**（我们用的）：

  ```bash
  until docker exec campus-mysql mysqladmin ping -h127.0.0.1 -uroot -p"$PASS" --silent; do
    echo "等待 MySQL 就绪..."; sleep 2
  done
  ```

- **healthcheck + depends_on condition**（Compose 版更优雅，见第八章练习）。

**这就是"进程存活"与"服务可用"的区别**，也是面试常问的"健康检查怎么做"。

### 2.9 开机自启

服务器重启后要自动恢复，需要两件事同时成立：

1. Docker 服务开机启动：`systemctl enable docker`；
2. 容器带重启策略：`--restart unless-stopped`（`always` 也行，但手动 stop 后它还会拉起，调试时不方便）。

## 第四章 手动部署步骤（不看脚本也能复现）

> 前提：Ubuntu 22.04、能 SSH 登录、防火墙已放行 8080。

**第 1 步 装 Docker**

```bash
sudo apt-get update
sudo apt-get install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER      # 让当前用户免 sudo 用 docker，需重新登录生效
docker version
```

**第 2 步 配镜像加速**（国内必须，否则拉 1GB 的 MySQL 要几十分钟）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{"registry-mirrors": ["https://mirror.ccs.tencentyun.com"]}
EOF
sudo systemctl restart docker
```

**第 3 步 建目录、传文件**

```bash
sudo mkdir -p /opt/campus/{sql,keys,uploads,data/{mysql,redis,rabbitmq}}
sudo chown -R $USER:$USER /opt/campus
# 本地执行：
scp app.jar ubuntu@IP:/opt/campus/
scp application-prod.yml ubuntu@IP:/opt/campus/
scp keys/*.txt ubuntu@IP:/opt/campus/keys/
scp init.sql ubuntu@IP:/opt/campus/sql/
chmod 600 /opt/campus/keys/*.txt
```

**第 4 步 建网络，起 MySQL**

```bash
docker network create campus

docker run -d --name campus-mysql --network campus \
  --restart unless-stopped \
  -e MYSQL_ROOT_PASSWORD='你的密码' \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/data/mysql:/var/lib/mysql \
  -v /opt/campus/sql:/docker-entrypoint-initdb.d:ro \
  mysql:8.0 --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci
```

**第 5 步 等它就绪并确认数据导入**

```bash
until docker exec campus-mysql mysqladmin ping -h127.0.0.1 -uroot -p'你的密码' --silent; do sleep 2; done
docker exec -it campus-mysql mysql -h127.0.0.1 -uroot -p'你的密码' -e "show databases; select count(*) from campus_trade.item;"
```

> 容器内连 MySQL 必须加 `-h127.0.0.1`，否则走 socket 会报 2002。

**第 6 步 起 Redis 和 RabbitMQ**

```bash
docker run -d --name campus-redis --network campus --restart unless-stopped \
  -v /opt/campus/data/redis:/data redis:7-alpine --appendonly yes

docker run -d --name campus-mq --network campus --restart unless-stopped \
  -e TZ=Asia/Shanghai -v /opt/campus/data/rabbitmq:/var/lib/rabbitmq \
  rabbitmq:3.13-management
```

**第 7 步 起应用**

```bash
docker run -d --name campus-app --network campus --restart unless-stopped \
  -p 8080:8080 \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/app.jar:/app/app.jar:ro \
  -v /opt/campus/application-prod.yml:/app/application-prod.yml:ro \
  -v /opt/campus/keys:/app/keys:ro \
  -v /opt/campus/uploads:/app/uploads \
  -w /app \
  eclipse-temurin:17-jre \
  java -Xmx512m -jar /app/app.jar --spring.config.location=file:/app/ --spring.config.name=application-prod
```

**第 8 步 验收（四道门逐层确认）**

```bash
docker ps                                  # 四个容器都 Up
docker logs --tail 50 campus-app           # 看到 Started CampusTradeApplication
ss -lntp | grep 8080                       # 宿主机在监听
curl -I http://127.0.0.1:8080/shop.html    # 宿主机内部 200
```

然后在**你自己的电脑**打开 `http://49.232.39.241:8080/shop.html`。打不开就按 2.1 的四道门往上查。

## 第五章 踩坑实录（都是真实发生过的）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 密钥传了仍 `Permission denied (publickey)` | 云网页终端默认是 **root**，公钥写进了 `/root/.ssh` | 改写到 `/home/ubuntu/.ssh`，`chown ubuntu:ubuntu`，权限 `700/600` |
| 2 | `ssh` 能连但 `sudo` 要密码，脚本卡住 | 非交互登录不能输密码 | 用 `ssh -t` 分配终端，或给部署用户配免密 sudo |
| 3 | `dockerd` 起不来，`status=1` | `daemon.json` 里 JSON 少了引号（shell 吃掉了） | 本地写好文件再 `scp` 上传，别在 ssh 命令里拼 JSON |
| 4 | 修完配置仍起不来，报 `Start request repeated too quickly` | systemd 对反复失败的 unit 会拉黑 | `sudo systemctl reset-failed docker` 后重启 |
| 5 | 容器内 `mysql` 报 `2002 socket` | 没指定 host 走的是 socket | 加 `-h127.0.0.1` |
| 6 | 应用起不来，`Connection refused` 到 mysql | `application.yml` 还写着 `localhost` | 生产配置写容器名 `campus-mysql` |
| 7 | 时间差 8 小时 / 中文乱码 | 容器默认 UTC、字符集不是 utf8mb4 | 所有容器 `-e TZ=Asia/Shanghai`；JDBC 加 `serverTimezone` + `characterEncoding`；MySQL 加 utf8mb4 启动参数 |
| 8 | 改了 `daemon.json`/配置后"改了没用" | 容器/进程没重启，或改的是宿主机配置而容器挂的是旧副本 | 改完必须 `docker restart <name>`，并确认挂载路径 |

## 第六章 日常运维手册

```bash
docker ps                          # 谁在跑
docker logs -f campus-app          # 应用日志（排错第一入口）
docker logs --tail 100 campus-mysql
docker restart campus-app          # 改完 jar / 配置后
docker exec -it campus-mysql mysql -h127.0.0.1 -uroot -p
docker exec -it campus-redis redis-cli
docker stats --no-stream           # 每个容器吃多少 CPU/内存
docker update --restart=no campus-app   # 临时关掉自动重启（调试用）
```

**备份数据库**（建议每周一次，到期前必做）：

```bash
docker exec campus-mysql mysqldump -uroot -p'密码' --single-transaction \
  --default-character-set=utf8mb4 campus_trade > /opt/campus/backup-$(date +%F).sql
```

**换机器时**只需搬三样：`app.jar`、`application-prod.yml`、`sql/init.sql`（+ 新的密钥、uploads 目录）。

## 第七章 面试问答（部署这块最常问的 12 个）

1. **你的项目怎么部署的？** 一台 Ubuntu 云服务器，装 Docker 后把 MySQL、Redis、RabbitMQ、应用分别跑在四个容器里，用一个自定义 bridge 网络互通，只有应用映射 8080，其余内网访问。
2. **为什么用 Docker？** 环境一致、版本隔离、迁移成本低；传统装法容易出现"我这能跑你那不能跑"。
3. **镜像和容器的区别？** 镜像是只读模板，容器是镜像跑起来的进程，可以起多个。
4. **数据怎么不丢？** 三个中间件的数据目录挂到宿主机 `/opt/campus/data`，容器重建数据仍在。
5. **容器之间怎么通信？** 同一个 bridge 网络里用容器名（Docker 内置 DNS），不用 IP。
6. **为什么应用配置里写 `campus-mysql` 而不是 localhost？** 容器有独立网络命名空间，`localhost` 指自己。
7. **端口映射和防火墙有什么区别？** 前者是 Docker 把宿主端口转发进容器，后者是云平台放行公网流量，两个都必须开。
8. **配置怎么和代码分离？** 启动参数 `--spring.config.location` 指向外置 `application-prod.yml`，jar 不改。
9. **启动顺序怎么保证？** 脚本轮询 `mysqladmin ping`；Compose 里用 healthcheck + `depends_on.condition`。
10. **线上内存怎么规划的？** 2C4G：应用 `-Xmx512m`、MySQL 缓冲池 128M、Redis/MQ 各几十 MB，空载约 1.2G。
11. **怎么排错"网站打不开"？** 四道门：进程监听 → 端口映射 → 防火墙 → 浏览器；从下往上。
12. **怎么保证重启后自动恢复？** `systemctl enable docker` + 容器 `--restart unless-stopped`。

## 第八章 进阶练习（自己动手才算会）

1. **用 `docker compose` 重写上面 8 步**：一个 `docker-compose.yml` 描述四个服务，`docker compose up -d` 一键起，体会"声明式"和"命令式"的差别。
2. **写一个 5 行的 Dockerfile 打包自己的 jar**：
   ```dockerfile
   FROM eclipse-temurin:17-jre
   WORKDIR /app
   COPY target/campus-trade-0.0.1-SNAPSHOT.jar app.jar
   ENTRYPOINT ["java","-Xmx512m","-jar","app.jar","--spring.config.location=file:/app/"]
   ```
   然后 `docker build -t campus-trade:v1 .` —— 这才是真正的"把应用做成镜像"。
3. **加 Nginx 反向代理**：Nginx 监听 80，转发到 `campus-app:8080`；有域名后可以上 HTTPS。
4. **加定时备份**：`crontab -e` 每天凌晨 dump 一次，保留 7 天。
