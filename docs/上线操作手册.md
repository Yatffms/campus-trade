> 这份文档是"照着敲"的版本：从本地打包、上传、到服务器起四个容器，全程命令 + 成功标志 + 报错处理。
> 配套阅读：`docs/部署方案.md`（讲原理：为什么这样做）、`docs/当前进度.md`（项目全貌）。
>
> 服务器：`49.232.39.241`（Ubuntu 22.04，2 核 4G）

## 0. 先记住两个窗口

整个流程只有两种命令：**在你电脑上执行的**、**在服务器上执行的**。混了就报 `Could not resolve hostname d` 这种错。

| 窗口 | 提示符长什么样 | 这里跑什么 |
|---|---|---|
| **本机 PowerShell** | `PS C:\Users\li176>` | `ssh`、`scp`、`dir`、`mvn` |
| **服务器（SSH 进去后）** | `ubuntu@VM-0-11-ubuntu:~$` | `docker`、`ls`、`chmod`、`curl` |

判断口诀：**有 `PS C:\` = 本机；有 `ubuntu@` = 服务器。**

建议开两个标签页并右键重命名成「本机」「服务器」。

## 1. 打包（本机 · IDEA 里操作）

1. IDEA 右侧竖排图标点 **Maven**；
2. 展开 `campus-trade → 生存期（Lifecycle）`；
3. 双击 **`package`**（不是 `clean`——`clean` 只是删 `target` 目录）；
4. 右下角出现 `BUILD SUCCESS`；
5. 确认产物：

```powershell
dir D:\idea\campus-trade\target\*.jar
```

看到两个文件：

```
campus-trade-0.0.1-SNAPSHOT.jar           83.6 MB   ← 这个要传
campus-trade-0.0.1-SNAPSHOT.jar.original   0.7 MB   ← 瘦包，不传
```

- 只有 `.original` 没有大 jar：说明 `spring-boot-maven-plugin` 没生效，检查 `pom.xml` 的 `build` 段。
- `BUILD FAILURE`：把最上面两行红字发出来（常见是测试失败，可先 `-DskipTests`）。

## 2. 登录服务器（本机 PowerShell）

```powershell
ssh -i D:\idea\.ssh\deploy_key ubuntu@49.232.39.241
```

- 第一次会问 `Are you sure you want to continue connecting (yes/no/[fingerprint])?` → **手输 `yes` 回车**（直接回车 = `Host key verification failed`）。
- 成功标志：提示符变成 `ubuntu@VM-0-11-ubuntu:~$`，并打印 Ubuntu 版本信息。

> 用户名一定是 `ubuntu`，不是 `root`（root 密码登录默认关闭）。

---

## 3. 建目录（服务器）

```bash
sudo mkdir -p /opt/campus/{sql,keys,uploads,data/mysql,data/redis,data/rabbitmq}
sudo chown -R ubuntu:ubuntu /opt/campus
ls -l /opt/campus
```

成功标志：看到 `sql keys uploads data`，属主 `ubuntu ubuntu`。

**为什么要 `chown`**：root 建的目录 ubuntu 写不进去，下一步 `scp` 会 `Permission denied`。

## 4. 上传文件（本机 PowerShell，先 `exit` 退出服务器）

```powershell
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\sql\init.sql" ubuntu@49.232.39.241:/opt/campus/sql/
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\keys\app_private_key.txt" "D:\idea\.deploy\server-backup\keys\alipay_public_key.txt" ubuntu@49.232.39.241:/opt/campus/keys/
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\application-prod.yml" ubuntu@49.232.39.241:/opt/campus/
scp -i D:\idea\.ssh\deploy_key "D:\idea\campus-trade\target\campus-trade-0.0.1-SNAPSHOT.jar" ubuntu@49.232.39.241:/opt/campus/app.jar
```

成功标志：每条显示进度行，最后一条 jar 约 1 分钟。

```
init.sql                100%   21KB   21.5KB/s   00:01
app_private_key.txt     100% 1624    1.6MB/s     00:00
campus-trade-...jar     100%   84MB   1.2MB/s     01:11
```

回服务器验收 + 锁密钥：

```bash
ls -lh /opt/campus /opt/campus/keys
chmod 600 /opt/campus/keys/*.txt
```

**为什么要 `chmod 600`**：密钥默认 664，服务器上任何用户都能读；600 = 只有属主能读。

## 5. 起 MySQL（服务器）

```bash
docker network create campus

docker run -d --name campus-mysql --network campus --restart unless-stopped \
  -e MYSQL_ROOT_PASSWORD=12345678 -e MYSQL_DATABASE=campus_trade -e TZ=Asia/Shanghai \
  -v /opt/campus/data/mysql:/var/lib/mysql \
  -v /opt/campus/sql:/docker-entrypoint-initdb.d:ro \
  mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci --default-time-zone=+08:00
```

**关键**：`-v .../sql:/docker-entrypoint-initdb.d:ro` 会让 MySQL 在**数据目录为空**时自动执行 `init.sql`。

等待就绪：

```bash
docker logs -f campus-mysql
```

成功标志：出现 `ready for connections. Version: '8.0.46' ... port: 3306`（按 `Ctrl+C` 退出查看，不影响容器）。

验证数据：

```bash
docker exec campus-mysql mysql -h127.0.0.1 -uroot -p12345678 -e "select count(*) from campus_trade.item;"
```

必须返回 **35**。（`-h127.0.0.1` 不能省，否则走 socket 报 `ERROR 2002`。）

## 6. 起 Redis 和 RabbitMQ（服务器）

```bash
docker run -d --name campus-redis --network campus --restart unless-stopped \
  -v /opt/campus/data/redis:/data redis:7-alpine redis-server --appendonly yes

docker run -d --name campus-mq --network campus --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/data/rabbitmq:/var/lib/rabbitmq \
  rabbitmq:3.13-management
```

验证：

```bash
docker ps
docker exec campus-redis redis-cli ping     # 返回 PONG
```

成功标志：`campus-mysql`、`campus-redis`、`campus-mq` 三行 `Up`。

## 7. 起应用（服务器）

```bash
docker run -d --name campus-app --network campus --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/app.jar:/app/app.jar:ro \
  -v /opt/campus/application-prod.yml:/app/application-prod.yml:ro \
  -v /opt/campus/keys:/app/keys:ro \
  -v /opt/campus/uploads:/app/uploads \
  -p 8080:8080 \
  eclipse-temurin:17-jre \
  java -Xmx512m -jar /app/app.jar \
  --spring.config.location=file:/app/ --spring.config.name=application-prod
```

看日志：

```bash
docker logs -f campus-app
```

成功标志（顺序出现）：

1. `:: Spring Boot :: (v3.3.5)`
2. `Tomcat started on port 8080 (http)`
3. `Created new connection: ... amqp://guest@...:5672/`
4. `HikariPool-1 - Start completed`
5. `Started CampusTradeApplication in 7.x seconds`

服务器内自测：

```bash
curl -s -o /dev/null -w 'HTTP=%{http_code}\n' http://127.0.0.1:8080/shop.html
```

`HTTP=200` 即成。

## 9. 以后更新版本（最常用）

改完代码只需要三步：**重新打包 → 只传 jar → 重启容器**，不用重建数据库和镜像。

```powershell
# 本机
dir D:\idea\campus-trade\target\campus-trade-0.0.1-SNAPSHOT.jar
scp -i D:\idea\.ssh\deploy_key "D:\idea\campus-trade\target\campus-trade-0.0.1-SNAPSHOT.jar" ubuntu@49.232.39.241:/opt/campus/app.jar
```

```bash
# 服务器
docker restart campus-app
docker logs -f campus-app     # 看到 Started ... 即可
```

> 注意：改了 `application-prod.yml` 也要重传 + 重启；改了数据库结构才需要动 MySQL。

## 10. 这些命令要不要背？

**不用背，但"会用"要有个准确含义**：能看懂每个参数在干什么、换个数能改对、报错能定位。具体分三档：

### 第一档：练到不用想（一共 6 条）

```bash
ssh -i D:\idea\.ssh\deploy_key ubuntu@49.232.39.241   # 进服务器
scp -i <key> <本地文件> ubuntu@IP:<服务器路径>          # 传文件
docker ps                                             # 看容器活着没
docker logs -f <容器名>                                # 看日志（最常用）
docker restart <容器名>                                # 重启
docker exec -it <容器名> bash                          # 进容器看一眼
```

这 6 条占日常 90% 的运维动作。

### 第二档：懂参数含义，会拼会改

`docker run` 是模板，**参数换掉就是另一个服务**：

| 参数 | 含义 | 换个值试试 |
|---|---|---|
| `-d` | 后台运行 | 去掉就占住终端 |
| `--name` | 容器名（也是网络里的域名） | `campus-app2` |
| `-p 8080:8080` | 宿主机端口:容器端口 | `-p 9090:8080` = 外网用 9090 |
| `-v 宿主机:容器` | 挂载（数据/配置/密钥） | 换目录 |
| `-e KEY=VALUE` | 环境变量 | 改密码、时区 |
| `--network` | 加入哪个网络 | 同一网络内可用容器名互访 |
| `--restart unless-stopped` | 开机/崩溃自动拉起 | 去掉就不会自愈 |

判断标准：**把 8080 换成 9090，你能自己把 `-p` 和防火墙都改对，就算"会用"了。**

### 第三档：用到再查

- 镜像 tag 具体有哪些（`docker search` / 官网）；
- MySQL 初始化脚本机制、`mysqldump` 参数；
- RabbitMQ 管理台地址与账号；
- Nginx 反向代理、HTTPS 证书；
- Dockerfile 多阶段构建、Compose 语法。

### 一句话结论

> **命令是"查得到的知识"，报错是"练出来的经验"。**
> 不用背命令，但要能一眼看出来"这是端口没开、这是路径不存在、这是服务没起来"。

面试时没人考你 `docker run` 的参数顺序，考的是：「你怎么部署的？出过什么问题？怎么定位的？」——那才是要背下来的部分（答案在你真踩过的坑里）。

## 11. 常见报错对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `Could not resolve hostname d` | 在服务器里跑了本机路径的命令 | 回本机 PowerShell 执行 `scp` |
| `Host key verification failed` | 提示 yes/no 时直接回车了 | 重连，手输 `yes` |
| `Permission denied (publickey)` | 用户名或密钥不对 | `ubuntu@` + `-i D:\idea\.ssh\deploy_key` |
| `scp: Permission denied` | 目录属主是 root | `sudo chown -R ubuntu:ubuntu /opt/campus` |
| `Conflict. The container name "/campus-app" is already in use` | 旧容器还在 | `docker rm -f campus-app` 再 run |
| `Communications link failure` | MySQL 还没就绪 | 等 `ready for connections` 后 `docker restart campus-app` |
| `Access denied for user 'root'` | 密码不一致 | 核对 `MYSQL_ROOT_PASSWORD` 与 yml |
| 库是空的（0 行） | `data/mysql` 非空，初始化脚本没跑 | `docker rm -f campus-mysql && sudo rm -rf /opt/campus/data/mysql/*` 重来 |
| 服务器内 200、外网打不开 | 防火墙没放行 | 控制台→防火墙→TCP 8080 |
| 中文乱码 | 编码 | `--character-set-server=utf8mb4` + JDBC `characterEncoding=utf8` |
