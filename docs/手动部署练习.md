# 手动部署练习（从零复现一遍）

> 目的：不看脚本、不让我代劳，你自己把这套东西从空服务器跑到公网能访问。
> 服务器已经清空：**没有容器、没有镜像、没有 /opt/campus**，只剩装好的 Docker 引擎（29.1.3）和 SSH 密钥。
> 每一步都给了「粘贴什么」「看到什么算成功」「卡住怎么办」。

## 第 1 步：登录服务器

在你电脑的 **PowerShell**（提示符是 `PS C:\Users\li176>`）里粘贴：

```powershell
ssh -i D:\idea\.ssh\deploy_key ubuntu@49.232.39.241
```

- 第一次会问 `Are you sure you want to continue connecting (yes/no/[fingerprint])?` → **手输 `yes` 回车**（直接回车会报 `Host key verification failed.`）。
- 成功标志：提示符变成 `ubuntu@VM-0-11-ubuntu:~$`。

> 判断自己在哪：`PS C:\Users\li176>` = 你自己的电脑；`ubuntu@VM-...` = 服务器。
> 下面的命令**除非特别说明，都在服务器里执行**。

## 第 2 步：拉四个镜像

```bash
docker pull mysql:8.0
docker pull redis:7-alpine
docker pull rabbitmq:3.13-management
docker pull eclipse-temurin:17-jre
```

- 成功标志：每条最后一行是 `Status: Downloaded newer image for xxx`，或 `Image is up to date`。
- 验证：`docker images` 应该看到 4 行。
- 卡住：`docker pull` 慢是正常的（几 GB），腾讯云内网镜像一般 2~5 分钟；如果报 `TLS handshake timeout`，重跑同一条即可。
- 卡在 `Pulling from library/mysql` 很久：看磁盘 `df -h /`，60G 够用。

---

## 第 3 步：建目录

```bash
sudo mkdir -p /opt/campus/{sql,keys,uploads,data/mysql,data/redis,data/rabbitmq}
sudo chown -R ubuntu:ubuntu /opt/campus
ls -l /opt/campus
```

- 成功标志：看到 `sql keys uploads data` 四个目录，属主是 `ubuntu ubuntu`。
- **为什么要 `chown`**：root 建的目录 ubuntu 用户写不进去，后面 `scp` 会 Permission denied。

---

## 第 4 步：上传文件（这一步在**你自己的 PowerShell**里执行）

**先退出服务器**（敲 `exit` 回车，提示符变回 `PS C:\Users\li176>`），然后粘贴这 4 条：

```powershell
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\sql\init.sql" ubuntu@49.232.39.241:/opt/campus/sql/
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\keys\app_private_key.txt" "D:\idea\.deploy\server-backup\keys\alipay_public_key.txt" ubuntu@49.232.39.241:/opt/campus/keys/
scp -i D:\idea\.ssh\deploy_key "D:\idea\.deploy\server-backup\application-prod.yml" ubuntu@49.232.39.241:/opt/campus/
scp -i D:\idea\.ssh\deploy_key "D:\idea\campus-trade\target\campus-trade-0.0.1-SNAPSHOT.jar" ubuntu@49.232.39.241:/opt/campus/app.jar
```

- 成功标志：每条最后显示 `xxx 100% 21549 21.5KB/s 00:01` 这样的进度行（jar 那条要 **1 分钟左右**，83.6MB）。
- 卡住：
  - `Permission denied (publickey)` → 密钥路径写错，或 `-i` 后面没加引号。
  - `No such file or directory` → 本地路径不对，先 `dir D:\idea\.deploy\server-backup` 确认文件在。
  - `Permission denied` 出现在服务器端 → 第 3 步的 `chown` 没做。

上传完重新登录服务器，检查：

```bash
ls -lh /opt/campus /opt/campus/sql /opt/campus/keys
```

应该看到 `app.jar`（84M）、`init.sql`（21K）、两个密钥（1.6K / 392B）、`application-prod.yml`（1.4K）。

**顺手把密钥锁死**（不然别人能读到你的私钥）：

```bash
chmod 600 /opt/campus/keys/*.txt
ls -l /opt/campus/keys
```

成功标志：两个文件权限都是 `-rw-------`。

## 第 5 步：起 MySQL

```bash
docker network create campus
docker run -d --name campus-mysql --network campus --restart unless-stopped \
  -e MYSQL_ROOT_PASSWORD=12345678 -e MYSQL_DATABASE=campus_trade -e TZ=Asia/Shanghai \
  -v /opt/campus/data/mysql:/var/lib/mysql \
  -v /opt/campus/sql:/docker-entrypoint-initdb.d:ro \
  mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci --default-time-zone=+08:00
```

**关键点**：`-v /opt/campus/sql:/docker-entrypoint-initdb.d:ro` 是"首次启动自动执行 init.sql"的机制——MySQL 镜像只在**数据目录为空**时执行 `/docker-entrypoint-initdb.d/` 下的脚本。所以 `data/mysql` 现在必须是空的。

等它就绪（要 20~40 秒）：

```bash
docker logs -f campus-mysql
```

成功标志：日志最后出现 `ready for connections.`（按 `Ctrl+C` 退出日志查看，不影响容器）。

验证数据真的进去了：

```bash
docker exec campus-mysql mysql -h127.0.0.1 -uroot -p12345678 -e "use campus_trade; select count(*) from item; select count(*) from user;"
```

- 成功标志：`item` 有 35 行、`user` 有 6 行（含软删除的测试商品，页面只显示在售 18 件）。
- 必须加 `-h127.0.0.1`：不加会走 socket，报 `ERROR 2002 (HY000)`。
- 密码错：`-p12345678` 中间不能有空格。

## 第 6 步：起 Redis 和 RabbitMQ

```bash
docker run -d --name campus-redis --network campus --restart unless-stopped \
  -v /opt/campus/data/redis:/data redis:7-alpine redis-server --appendonly yes

docker run -d --name campus-mq --network campus --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/data/rabbitmq:/var/lib/rabbitmq \
  rabbitmq:3.13-management
```

```bash
docker ps
```

成功标志：`campus-mysql`、`campus-redis`、`campus-mq` 三行都是 `Up`。

验证 Redis：`docker exec campus-redis redis-cli ping` → 回 `PONG`。
验证 MQ：`docker exec campus-mq rabbitmqctl status | head -5`（第一次要等十几秒）。

---

## 第 7 步：起应用

```bash
docker run -d --name campus-app --network campus --restart unless-stopped \
  -e TZ=Asia/Shanghai \
  -v /opt/campus/app.jar:/app/app.jar:ro \
  -v /opt/campus/application-prod.yml:/app/application-prod.yml:ro \
  -v /opt/campus/keys:/app/keys:ro \
  -v /opt/campus/uploads:/app/uploads \
  -p 8080:8080 \
  eclipse-temurin:17-jre \
  java -Xmx512m -jar /app/app.jar --spring.config.location=file:/app/ --spring.config.name=application-prod
```

看启动日志：

```bash
docker logs -f campus-app
```

成功标志（按顺序出现）：

1. `:: Spring Boot :: (v3.3.5)`
2. `Tomcat started on port 8080 (http)`
3. `Created new connection: ... amqp://guest@...:5672/`（连上 MQ）
4. `HikariPool-1 - Start completed`（连上 MySQL）
5. `Started CampusTradeApplication in 7.x seconds`

服务器内自测：

```bash
curl -s -o /dev/null -w 'HTTP=%{http_code}\n' http://127.0.0.1:8080/shop.html
```

成功标志：`HTTP=200`。

## 常见错误对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `Host key verification failed` | 没输 `yes` | 重新 ssh，手输 `yes` |
| `Permission denied (publickey)` | 用户名/密钥不对 | 必须是 `ubuntu@` + `-i D:\idea\.ssh\deploy_key` |
| `scp: Permission denied` | 服务器目录属主是 root | 第 3 步的 `chown -R ubuntu:ubuntu` |
| `Error response from daemon: Conflict. The container name ... is already in use` | 容器还在 | `docker rm -f campus-xxx` 再跑 |
| MySQL 起来但 `campus_trade` 是空的 | `data/mysql` 不是空的，初始化脚本没执行 | `docker rm -f campus-mysql && sudo rm -rf /opt/campus/data/mysql/*` 再来 |
| 应用日志 `Communications link failure` | MySQL 还没就绪 | `docker logs campus-mysql` 等 `ready for connections` 后 `docker restart campus-app` |
| 应用日志 `Access denied for user 'root'` | 密码不一致 | 检查 `application-prod.yml` 与 `MYSQL_ROOT_PASSWORD` |
| 浏览器打不开、服务器内 200 | 防火墙没放行 8080 | 控制台→防火墙→加 TCP 8080 |
| 界面中文乱码 | 库/连接编码 | `--character-set-server=utf8mb4` + JDBC `characterEncoding=utf8` |

## 验收标准

不看这份文档，能在**两小时**内把这 8 步重复一遍，并说出每一步"为什么"：

- 为什么 jar 要挂载而不是 COPY；
- 为什么 MySQL 要挂两个卷（数据 + 初始化脚本）；
- 为什么容器之间用 `campus-mysql` 这个名字而不是 `localhost`；
- 为什么 `-p 8080:8080` 之后还要在控制台放行 8080；
- 为什么密钥要 `chmod 600`。

做到这五条，部署这关就真的过了。
